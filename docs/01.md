# 자바 플랫폼의 이해와 구성 요소

## 자바 플랫폼이란

> 플랫폼 정의 : 어플리케이션 실행을 위한 기반이 되는 시스템

- 자바 프로그램이 실행될 수 있는 환경과 이를 지원하는 도구 세트를 의미
- 자바 어플리케이션이 개발, 배포, 실행을 위한 프레임워크와 런타임 환경을 제공

## 자바 플랫폼 에디션

> 특정 용도에 맞게 설계된 서로 다른 플랫폼

- Java SE(Standard Edition)
    - 자바의 표준 에디션으로 자바의 표준 플랫폼을 말한다.
    - 자바 프로그램 개발의 핵심 API와 도구를 포함하고 있다.
    - JVM(Java Virtural Machine)을 포함하고 있다.

- Java EE(Enterprise Edition)
    - Java SE의 확장판으로 기업 환경에서 사용할 수 있는 서버측 어플리케이션 개발을 위해서 설계되었다.
    - 웹 어플리케이션, RESTful 서비스, 마이크로서비스 개발에 필요한 기술 스택을 포함한다.
    - 주요 구성 요소
        - Servlet, JSP, JPA(DB연동을 위한 ORM), JMS(메시지 기반 어플리케이션 개발) 등

- Java ME(Micro Edition)
    - 자바의 경량화된 버전으로 임베디드나 모바일 장치에서 자바를 사용할 수 있도록 설계되었다.
    - 2000년대 초반 피처폰이나 임베디드 디바이스에서 표준으로 자리잡았으나, 스마트폰 등장 이후 활용도가 줄어들었다.
    - 여전히 IoT 환경에서 사용된다.

## JVM 이란

- Java Virtual Machine
- 자바 플랫폼의 핵심 구성 요소로서 자바 프로그램이 운영체제에 관계없이 실행될 수 있도록 자바 코드(정확히 말하면, 컴파일된 자바 바이트 코드인 `.class` 파일을 말함)를 번역해준다.
- 운영 체제와 자바 어플리케이션 사이의 중간층 역할을 한다.

### 궁금한 점

> JVM은 운영체제 따라 다른 버전을 설치하여, 자바코드가 운영체제에 맞는 기계어로 번역되도록 도와준다. 그렇다면 이것은 운영체제에 의존적이지 않나?

> > 관점에 따라 다르다!

- JVM 관점
    - 자바 프로그램은 **운영체제별로 호환되는 JVM**을 통해서 실행된다. 그렇기 때문에 자바의 실행 기반은 운영체제에 의존적이다.
- 자바 코드(or 바이트 코드) 관점
    - 자바 코드는 운영체제에 관계없이 동일한 바이트 코드(`.class`)로 컴파일 된다. 컴파일된 바이트 코드는 어떤 JVM 에서든 동일하게 실행되기 때문에 자바 어플리케이션은 플랫폼 독립적이다.

→ 결과적으로 WORA(Write Once, Run Anywhere)을 실현하는 환경을 제공하는 필수 요소가 JVM 이라고 할 수 있다.

## JRE 란?

- Java Runtime Environment
    - 자바 어플리케이션을 실행하기 위한 필수 실행 환경으로서 자바 플랫폼 에디션에서 자바 어플리케이션을 실행하기 위한 필수적인 패키지이다.
- 구성
    - JVM : 바이트 코드 해석, 메모리 관리, 가비지 컬렉션, 스레드 관리등 핵심적인 역할 수행
    - Java Class Library : 자바 어플리케이션이 실행될 때 필요한 표준 라이브러리(API)

### JDK와의 관계

- Java Development Kit
- JDK는 개발자들이 자바 개발을 위해 사용되는 일종의 개발 도구 키트(SDK)이다.
- JRE는 JDK의 일부이다.
- 자바 프로그램을 개발하기 위해선 JDK가 필요하고, 자바 프로그램을 실행하는데는 JRE가 필요하다. 즉 JDK를 설치하면 자바 어플리케이션을 개발하고 실행시킬 수 있다.
